## 二、任务 6：AutoMeasureSort（基于 Hardware_control.ino）

### 目标
基于学长已验证的 `Hardware_control.ino`（同型号主控板），修改程序逻辑实现：
**上电 → 立即启动传送带 → 物体送到测量工位 → 触发 K230 → K230 确认检测到物体才返回 → 返回结果 + 分选 → 循环**。
要求 K230「未检测到物体不得提前返回」。

### grill 追问结论（常规强度）

|---|---|---|
| Q1 | 「到位检测」怎么判 | **K230 视觉即到位**（本硬件无超声、无到位传感器） |
| Q2 | K230 返回内容 | 「标签 置信度」 |
| Q3 | 是否改 K230 侧 | **授权**（连同 `det_video.py` 一起改） |
| Q4 | 检测到后做什么 | 返回信息 + 开始分选 |
| Q5 | 输出位置 | **新建一份**，不改 reference 原件 |
| Q6 | 上报通道 | USB Serial + HMI 屏，暂不做网络 |
| Q7 | 传送带数量 | 三级 Out1/2/3 |
| Q8 | 分选动作 | 分选电机 6 位置 + 开合电机 80°（闭环 3200 脉冲/圈） |
| Q9 | HMI 发送格式 | 沿用 `GeometricSortingTest.ino`：`t0.txt` + `t1.val`/`t2.val` |

### architect 架构对比与选型
- 方案 A｜最小改动·保留参考程序轮询结构
- 方案 B｜非阻塞状态机重构
- 方案 C｜折中·复用板级函数 + 状态机主循环

**选定方案 B**。决定性理由：该流程本质是顺序状态机，非阻塞是嵌入式稳健标准；且已有同硬件、已编译验证的状态机（`GeometricSortingTest.ino`）与诊断模块（`diaglog.h`）可直接迁移，改动风险最低。

### 状态机
```
上电 ─立即─▶ 启动三级传送带
  ▼
RUN      周期发 "image"；物体进视野（=到达测量工位）
  ▼ K230 确认检测到才回 "<标签> <置信度>"
DETECTED 停三级传送带 → HMI 显示 + USB 串口输出 RESULT
  ▼
SORT     分选电机转到 6 位置之一
  ▼
RELEASE  开合电机打开 80°（≈711 脉冲）
  ▼
DELAY    落料停留 1s
  ▼
RESET    开合关闭 + 分选复位 → 重启三级传送带 → 回到 RUN（循环）
```

### 关键参数
- 闭环步进 **16 细分 = 3200 脉冲/圈**；分选 6 位置；开合 80° ≈ 711 脉冲。
- 分选速度 300 步/s，开合 400 步/s；`VISION_WAIT_MS=500`（超时重发 image）；`RELEASE_DELAY_MS=1000`。
- 分选位置当前为「随机 6 选 1」，类别→盒位映射待定。

### K230 侧改动（det_video.py，两处）
1. **空读保护**：`uart.read(10)` 无数据时返回 `None`，原代码 `None.decode()` 会**抛异常直接退出脚本**（这正是之前 K230 完全不回应的最可能根因）；现加 `if text is None or len(text)==0: continue`。
2. **未检测到不提前返回**：删掉无物体时的 `uart.write("No objects were identified.")`，只有确认检测到（score>0.6）才回结果。

### HMI 发送格式（与 GeometricSortingTest.ino 对齐）
TJC 指令 `<控件>.<属性>=值` + 结束符 `0xFF 0xFF 0xFF`：

| 指令 | 含义 |
|---|---|
| `t0.txt="..."` | 文本 |
| `t1.val=N` | 颜色编号 1..13 |
| `t2.val=N` | 形状编号 1..31 |

标签为数字 ID(0..402) → `颜色=id%13+1`、`形状=id/13+1`，发 t1/t2；标签为名称 → 发 `t0.txt="DETECT"`。

## 三、关键结论 / 洞察

1. **到位检测与确认检测合一**：无到位传感器时，用「K230 看到物体 = 到位」，天然满足「未检测到不提前返回」。
2. **K230 不回应的根因**：`det_video.py` 的 `uart.read(10)` 空读返回 `None`，`None.decode()` 崩溃退出脚本。
3. **诊断日志的价值**：实机 dump 明确显示 `BOOT→PROBE→(3秒超时)→HALT`，直接锁定「K230 未响应」，避免盲目排查。
