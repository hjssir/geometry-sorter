## 二、关键发现（3 项）

### 1. 原整合版「触发停止」时序与用户描述相反
原代码流程是「传感器逐级停带 → 停 3 号 → 才发 `image` 触发 K230」，K230 结果**不**触发停带。
用户最终选定**方案 B**（K230 持续发状态信息、由 Arduino 据状态控制传送带），与原代码时序不同，后续主程序需按方案 B 重写。

### 2. K230 实际协议已确认（来自 reference/det_video.py）
- 串口：UART2（引脚 11=TXD、12=RXD），115200。
- Arduino → K230：发送 `image` 触发一次识别。
- K230 → Arduino：识别到且最高分 > 0.6 → 回 `<标签> <置信度(2位)>
`（标签来自 K230 上 `deploy_config.json` 的 `categories`，如 `红球体 0.95`）。
- 无目标 → 回 `No objects were identified.`（无换行）。
- 与 Arduino 侧 vision.cpp 预设的「格式1：`<标签> <置信度>
`」及「No objects」判定一致。
- ⚠️ **待澄清**：该程序是「`image` 触发式」，与方案 B 描述的「K230 持续发状态」仍有出入，需确认是否要改成持续上报。

### 3. 新电机是「闭环步进电机」，不是 A4988 开环步进
- 型号：张大头(ZHANGDATOU) ZDT 闭环步进电机（X42S 第二代 / Y42 / Y57，Emm_V5.0 固件，另有 X 固件）。
- 内置驱动器+编码器（闭环）：有堵转保护、不易丢步，可读实时位置/转速/位置误差。
- 两种控制方式：**脉冲控制（PUL/DIR/ENA）** 或 **串口控制（UART/RS232/RS485，位置/速度模式，MODBUS 或厂家私有协议）**。
- 默认 **16 细分 = 3200 脉冲/圈**（旧 A4988 为 1/8 细分 1600 步/圈）。

## 八、主测试程序已完成（方案 B）

在 `GeometricSorting/GeometricSortingTest/` 新建：

| 文件 | 说明 |
|---|---|
| `GeometricSortingTest.ino` | 方案 B 主测试程序（单文件，上电自跑，约 520 行） |
| `README.md` | 流程图、接线、参数、烧录、日志示例 |

实现要点：
- 状态机：`BOOT → PROBE → FEED → VISION → DISPLAY → SORT → RELEASE → DELAY → RESET →(循环) FEED`，另含 `HALT`。
- 上电等 K230 10s → 探测（发 image 看有无响应）→ 未接入则 HALT 停机。
- VISION 循环发 `image` 轮询：收到有效标签 → 停三级传送带；`No objects`/超时 → 继续送带重发。
- 视觉收帧：换行结束帧 + 静默期(20ms)结束帧，兼容「`标签 置信度`」与无换行的 `No objects`。
- HMI：发 t1.val(颜色编号)/t2.val(形状编号)，控件名与 ji.HMI 一致。
- 分选：随机 6 选 1；开合 80°(≈711 脉冲)；闭环电机 3200 脉冲/圈。
- 保留 `SIMULATION_MODE` 开关（默认 0）用于无硬件逻辑预演。

## 九、全流程自检（2026-10-16）

### 1. 真实语法编译（avr-g++ 7.3.0 + Arduino AVR core 1.8.8 + AccelStepper）
- 结果：**0 错误、0 警告**（`-fsyntax-only -Os -Wall`，ATmega2560）。
- 自检中发现并修复：
  1. 枚举名 `DISPLAY` 与 Arduino.h 的 `#define DISPLAY 0x1` 宏冲突 → 改名 `SHOW`。
  2. `visionRequest()` 发 `image` 前增加 `while(Serial2.available()) Serial2.read()` 清空残留旧帧，避免上一轮结果串扰。

### 2. 逻辑走查（SIMULATION_MODE=1 模拟）
状态迁移闭环验证通过：
```
BOOT → PROBE → FEED → VISION → SHOW → SORT → RELEASE → DELAY → RESET →(循环) FEED
（K230 无响应：PROBE → HALT）
```
- 传送带：FEED 三级全启动 → VISION 收有效结果三级全停 → RESET 三级重启。
- 分选：SHOW 随机位置 → SORT 等待到位 → RELEASE 开合打开 → DELAY 落料 1s → RESET 关闭+复位。
- HMI：SHOW 发 t1.val(颜色编号)/t2.val(形状编号)。
- K230：VISION 循环发 image；`No objects`/超时 → 继续送带重发；有效标签 → 停带。
- 待硬件联调项：K230 实际回传格式（数字 or 名称）、分选 6 位置精度、落料 1s 时长。

## 十、离线诊断日志模块（diaglog.h）

针对「上电后传送带短暂运行即停 / 分选正常 / 开合未按预设角度」的离线诊断需求，新增 EEPROM 持久化日志模块。

### 决策（用户已确认）
- 运行程序：方案 B（GeometricSortingTest.ino）；存储：内置 EEPROM(4KB)；回读：事后接串口 dump；VCC+复位检测都加；记录 5 个循环后停止。
- 电源：步进独立供电、与主控共地；传送带 OUT1/2/3 直接供电；开合电机 3200 脉冲/圈、方向正确。

### 实现
- 新建 `GeometricSortingTest/diaglog.h`（头文件模块），集成进主程序（11 处埋点）。
- EEPROM 布局：头部 16 字节（魔数/版本/上电次数/循环计数/写指针/复位前状态）+ 记录区（每条 10 字节，最多 408 条，环形覆盖）。
- 记录类型：BOOT / STATE / CONV / SORTER / GATE / K230 / VCC / CYCLE / RESET。
- VCC 用内部 1.1V 带隙反测（毫伏）；复位检测靠「上次状态非空且未到循环边界」。
- 串口命令：`d`=dump 回读、`c`=clear 清空。
- 已通过 avr-g++ 语法编译（0 错误 0 警告）。

### 待硬件联调
- 上机后：复位设备 → 跑 5 个循环 → 接串口发 `d` 回读，重点看 GATE 记录的目标步数与 VCC 变化，定位开合角度异常根因。
