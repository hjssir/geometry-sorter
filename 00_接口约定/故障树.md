# 故障树（现象 → 模块 → 你先做 → 何时转交）

- 用法：**先按现象定位模块，再做"你先做的初步排查"；只有做完还不行才转交**，转交时带上"我已经排除了什么"
- 前置：三张分模块自检表（主控单独测 / K230 单独测 / HMI 单独测）见 §2；三张各自通过后再合体
- 来源：整合 AI 计划 3.3 的 15 条 + 2026-10-18 核验新增 6 条

---

## 1 现象 → 模块 → 排查 → 转交

| # | 现象 | 最可能模块 | 你先做的初步排查 | 什么情况转交 |
|---|---|---|---|---|
| 1 | 上电 13 秒后全部停住 | 主控（烧错程序） | 确认烧的是 **AutoMeasureSort**，不是 `GeometricSortingTest`（PROBE 死锁）或整合版（`SIMULATION_MODE=1`） | 是 AMS 仍停机 → 看 `ERROR` 日志是 PROBE 失败还是 MISS |
| 2 | 屏全黑 / 毫无反应 | HMI（波特率/供电/接线） | USB-TTL 直发指令，9600 与 115200 各试一次 | 单独测也不动 → **转交 HMI** |
| 3 | 屏有字但数字不更新 | HMI（控件类型） | 看 `t0.txt` 能否变（能变=线通）；确认 `t1/t2` 是不是数字控件 | 确认仍是文本控件 → **转交 HMI 改类型** |
| 4 | 屏显示乱码 / 方块 | HMI（编码 GB2312 vs UTF-8） | 改发英文/数字试 | 英文正常、中文乱码 → **转交 HMI** |
| 5 | 传送带完全不转 | 主控 / 硬件 | 万用表量 A1/A2/A3 电平；程序里手动置高测一次 | 引脚有电平但带不转 → 继电器/供电，**不是软件** |
| 6 | 带一直转、永不识别 | K230→主控链路 | 看日志有没有 `id=` / `NONE`：都没有 → K230 没回 | 完全没回 → 电脑串口助手直接发 `image` 测；仍不回 → **转交视觉** |
| 7 | K230 第一次就不回 | 视觉 / 物理层 | 电脑串口助手发 `image` 给它 | 电脑发也不回 → **转交视觉**（脚本崩/没跑起来/波特率） |
| 8 | 前几件正常，某件之后 K230 永久不回 | 视觉（`color_four` 越界） | 重启 K230 是否恢复 | 是 → 几乎确定调色板 80 项越界 → **转交视觉** |
| 9 | 日志 `id=-1` 但流程继续 | 视觉（回包形态是中文名） | 看日志 `标签=` 后是中文还是数字 | 中文 → **转交视觉**改数字 id |
| 10 | 分选位置偏一格 / 偏半格 | 主控（原点/映射） | 手动逐位对盒；量 3200 脉冲是否正好 1 圈 | 脉冲对但盒位错 → 原点假设 → 上电人工对位 |
| 11 | 开合角度不对 | 主控（参数） | 确认是 3200/711 而不是 3500/777 | 参数对仍不对 → 方向/堵转/机械卡滞 |
| 12 | 卡在 SORT 或 RELEASE 不动 | 电机 / 驱动 / 缺看门狗 | 看日志有没有"到位"行；手转看是否卡滞 | 有使能不动 → 脉冲线/驱动器；转但不到位 → 堵转/负载；都会卡死 → 阶段 1 加 `SORT_TIMEOUT` |
| 13 | 同一件被分选两次 | 机械节拍 / 主控 | 看两次的 `id` 是否相同；物料是否真掉下去 | 物料没掉落 → 机械；时间太短 → 加 `RELEASE_DELAY_MS` |
| 14 | 跑一会儿 Arduino 自动重启 | 电源 | diaglog 看 `RESET` 记录 + VCC 是否跌落 | VCC 跌 → 电源容量/共地，**不是代码**。注意：正常断电也记 RESET，别单凭它判断 |
| 15 | 指令发出去了屏没反应，但屏单独测是好的 | HMI（接线/共地） | 量 Mega TX18 是否有波形；屏 RX 是否接对 | 有波形、屏单独能收 → 共地/线序；否则转交 HMI |
| **16** | **每件都"停带 + 空放一次"** | **主控（`NONE` 被当标签）** | 日志里看是否有 `标签=NONE 置信度=100%` | 是 → 见《接口约定单》N1，加 4 行判断 |
| **17** | **真机开机即 ERROR / 探测失败** | **主控 + 视觉（PROBE 缺底层应答）** | 查 `det_video.py` 是否已发 `NONE`；PROBE 期间视野有无物体 | 没发 `NONE` → 先做 N1，再谈 PROBE（否则真机 100% 失败） |
| **18** | **上电全不动（带/电机/屏都不动）** | **主控（误烧整合版）** | 看程序名；整合版默认 `SIMULATION_MODE=1`，所有 IO 被短路 | 是整合版 → 重烧 AMS；阶段 4 归档时把 SIMULATION 改 0 并在 README 红字标注 |
| **19** | **运行中发 `d` 后电机丢步/憋停** | **主控（dump 阻塞）** | 停机时再 dump 一次对比 | dump 同步打印 408 条，会 1~2 s 不调 `run()` → 改分片打印 |
| **20** | **长时间跑后半段没有日志** | **主控（diaglog 上限）** | 数循环次数是否 >5 | diaglog 写满 408 条/5 循环即停写 → 阶段 4 长跑前必须放宽 |
| **21** | **想按屏上按钮急停没反应** | **HMI（未开发功能）** | 查代码有无 `Serial1.read` 与按钮指令 | 从来没有 → 属未开发，不是故障；本轮用串口 `e` + 物理急停 |

## 2 合体前的三张分模块自检表

### 2.1 主控单独测（不接 K230、不接屏）

| 检查项 | 怎么测 | 通过标准 |
|---|---|---|
| 程序跑起来 | USB 串口 115200 看日志 | 启动横幅 + 状态迁移日志 |
| 状态机推进 | 观察 20 s | `BOOT→PROBE`，探测失败进 `ERROR` 而不是傻等 |
| 三级传送带 | 上电看 | 3 条都转、方向一致 |
| 电机使能 | 发一次单轴动作 | 有保持力矩（手拧不动） |
| 分选轴 | 发 3200 脉冲 | 正好 1 圈（±2°） |
| 开合轴 | 发 711 脉冲 | ≈80°（±2°） |
| diaglog | 发 `d` | 能 dump 出 `BOOT` 记录 |

### 2.2 K230 单独测（不接 Mega）

| 检查项 | 怎么测 | 通过标准 |
|---|---|---|
| 摄像头 | 接屏看画面 | 正常无花屏 |
| 模型 | 放一个几何体 | 屏上画出框 |
| 串口回包 | 电脑串口助手 115200 发 `image` | 收到 `37 0.87\n`（或改造前中文名） |
| **回包形态** | **原始字节逐字节记录** | **确认是数字还是中文**（C-3 的最终答案） |
| 未识别 | 视野清空发 `image` | 应回 `NONE\n`（没回 = 视觉没改） |
| 单帧耗时 | 10 次平均 | 得到 ms 值写进参数表 |

### 2.3 HMI 单独测（不接 Mega，USB-TTL 直接灌）

| 检查项 | 怎么测 | 通过标准 |
|---|---|---|
| 波特率 | 9600 / 115200 各发一次 `t0.txt="hi"` + `FF FF FF` | 只有一个生效——**记下是哪个** |
| 文本控件 | `t0.txt="测试"` | 出字（乱码=编码问题） |
| 数字控件 | `t1.val=7` | 屏上显示 7（说明已改好类型） |
| 错误码 | 观察 USB-TTL 回包 | 能收到 `1C FF FF FF` 等错误码 → 屏在回应 |

## 3 合体时的分层排查顺序（为什么是这个顺序）

**屏 → 电脑模拟 K230 → 主控→K230 触发 → 真 K230 → 电机/传送带 → 整机**

- **先屏**：纯单向输出，最容易独立验证，且能立刻确定 9600/115200
- **再电脑模拟 K230**：排除 K230 侧不确定性，直接验证 Arduino 解析器；此步通过后真 K230 不通，就一定在 K230 侧
- **再主控→K230**：USB-TTL 并到 Serial2 TX 监听，确认"发得出去"
- **再真 K230**：此时只剩视觉侧变量
- **最后执行机构**：它们会**掩盖**通信问题（皮带一转，你以为正常，其实是没收到结果）

> 每步只改一个变量。很多"整机不工作"最后发现是**两个人同时改了东西**——这就是为什么阶段 1 要先冻结接口约定。
