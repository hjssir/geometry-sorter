## 4 节拍预算（2026-10-18 核验修正，**与 B1 冲突**）

AI 报告算的"10~15 s/件"只算了距离/速度，**漏了加减速、回程、开合、落料停留**。

| 项 | 估算 |
|---|---|
| 分选去程（均 2.5 位=1333 步 @300 步/s，含加减速） | ≈6.4 s |
| 分选回程（`sorterHome`，`AMS:296`） | ≈6.4 s（均值） |
| 开合 开 + 关（711 步 @400 步/s） | ≈2×1.8 s |
| 落料停留 | 1.0 s |
| **单件合计** | **≈17 s（均） / ≈26 s（最坏 0→5）** |

**冲突**：已确认的 B1 是"8~15 s/件" → 待裁决 D1：提速（300→800~1600 步/s）或改验收口径；且阶段 3 的"20 循环"实际约需 **6~9 分钟**，排班和验收标准都要按这个来。

## 6 diaglog 能力边界（`diaglog.h`）

| 项 | 值 | 影响 |
|---|---|---|
| 事件类型 | 9 类（全为"正常动作"） | 缺 `MISS / TIMEOUT / OFFLINE` 事件 → 掉线/漏检**零证据** |
| 每条大小 / 容量 | 10 B / 408 条 | — |
| K230 事件 id 字段 | **8 位**（`diaglog.h:130`） | 403 类中 id≥256 被截断混同 |
| 记录上限 | **5 个循环后停写**（`diaglog.h:33,137`） | 阶段 4 的"50 循环长跑"后半段无日志 |
| `RESET` 语义 | 上电只要上次状态 ≠0xFF 就记（`:166-169`） | 正常断电也记 RESET → "自动重启"判据失效 |
| 命令 | `d` = dump、`c` = clear（单字符） | `dump`/`clear` 注释是错的 |
| dump 阻塞 | 同步打印 408 条 | 运行中发 `d` 会 1~2 s 不调 `run()`，可能丢步/憋停 |
