## 2 必须和本文一起落地的两条实现裁决（2026-10-18 三方核验新增）

### N1 `NONE` 不是"改视觉就行"——主控必须加 4 行

**现状（已核到行）**：`finishFrame()` 只特判前缀 `No objects`（`AutoMeasureSort.ino:180`）；`NONE` 会被当成正常标签：
`vLabel="NONE"`、`vConf` 默认 **1.0**（`:182-189`）→ `updateRun()` 得 `r==1` → **停三级传送带**（`:253`）→ 打印 `RESULT:NONE,1.00` → `labelToId()=-1` 走 WARN（`:276`）→ **仍然随机选位并落料**（`:280`）。

**后果**：每来一次空视野，就误停带 + 空放一次分选，节拍被吃光；"空载/漏检/掉线"三态依旧不可区分。

**裁决**：在 `AutoMeasureSort.ino:180` 之后加 4 行，并把 `updateRun()` 的 `r==0` 显式计入"漏检一次"：

```cpp
// 在 finishFrame() 的 "No objects" 分支之后
if (strncmp(p, "NONE", 4) == 0) { vlen = 0; vbuf[0] = '\0'; return 0; }
```

> 结论：约定里"Arduino 解析器不动"这一条**作废**——允许且必须加这 4 行。它属于阶段 1 的 1-4，不是视觉同学的工作。

### N2 PROBE 在线判定必须依赖 `NONE`

当前 `det_video.py` 未识别时**什么都不发**（`:238-240`）。若直接按阶段 1-2 实现 `BOOT→PROBE`，真机开机时视野里没物体 → 等不到任何字节 → **PROBE 必然超时 → ERROR**，阶段 1 的验收在真机上 100% 失败。

**裁决**：`N1` 必须先于 `1-2` 落地；`PROBE` 的判据写成"收到任意**合法帧**（含 `NONE`）即在线"。

## 3 待定项（阻塞联调，必须由人回答）

| # | 项 | 要谁回答 | 不回会怎样 |
|---|---|---|---|
| 1 | 实际烧录 `.tft` 的波特率：9600 还是 115200 | HMI | 屏可能完全不响应，且无法从代码判断 |
| 2 | `t1/t2` 是否已改成数字控件、显示范围 | HMI | 屏上数字永远不动（最高概率故障） |
| 3 | `categories` 条数、内容形态、排列顺序是否"形状主序×13 色" | 视觉 | 颜色/形状编号全错，但流程照跑（静默失败） |
| 4 | 单帧识别耗时（10 次平均，ms） | 视觉 | 500 ms 重发周期是猜的，可能吞触发 |
| 5 | 缺 `deploy_config.json` / `.kmodel` | 视觉 | 无法独立复核类别表 |
| 6 | 缺 `.tft` 编译产物 | HMI | 无法确认现场烧的是哪一版 |
| 7 | 上电 9 字节 `printh` 是否保留 | HMI | 无法做"屏在线"握手（不阻塞本轮） |
