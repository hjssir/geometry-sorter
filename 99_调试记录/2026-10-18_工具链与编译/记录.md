## 3 操作（可复现）

```powershell
# 方式一：脚本（推荐）
.\10_主控_Arduino\compile.ps1              # 编译
.\10_主控_Arduino\compile.ps1 -Upload -Port COM5   # 编译 + 烧录

# 方式二：裸命令（注意 Arduino 要求 sketch 目录名 = .ino 名，故暂存到 _build/AutoMeasureSort/）
arduino-cli compile --fqbn arduino:avr:mega --warnings more --output-dir _build/out _build/AutoMeasureSort

# 方式三：不链接、只语法检查（最快，不依赖 arduino-cli）
$core = "$env:LOCALAPPDATA\Arduino15\packages\arduino\hardware\avr\1.8.8"
$gxx  = "$env:LOCALAPPDATA\Arduino15\packages\arduino\tools\avr-gcc\7.3.0-atmel3.6.1-arduino7\bin\avr-g++.exe"
& $gxx -x c++ -fsyntax-only -Wall -Os -mmcu=atmega2560 -DF_CPU=16000000L -DARDUINO=10819 `
  -DARDUINO_AVR_MEGA2560 -DARDUINO_ARCH_AVR `
  -I "$core\cores\arduino" -I "$core\variants\mega" -I "$core\libraries\EEPROM\src" `
  -I "10_主控_Arduino" -I "$env:USERPROFILE\Documents\Arduino\libraries\AccelStepper\src" `
  "10_主控_Arduino\AutoMeasureSort.ino"
```

> ⚠️ 踩坑记录：`compile.ps1` 刻意写成 **ASCII-only**。Windows PowerShell 5.1 会把**无 BOM 的 `.ps1` 按 ANSI 编码读取**，脚本里的中文注释会被解码成乱码并破坏引号，直接 `ParserError`。以后改这个脚本别加中文；要加中文先存成 UTF-8 with BOM。

## 4 实际结果

| 项 | 结果 |
|---|---|
| 编译退出码 | **0** |
| 错误 | **0** |
| 警告（`--warnings more` = `-Wall`） | **0** |
| 语法检查（`-fsyntax-only -Wall -Os`） | 0 错 0 告警（0 行输出） |
| Flash 占用 | **17,824 B（7%）**，上限 253,952 B |
| 全局变量 | **1,369 B（16%）**，剩 6,823 B 给栈/局部变量 |
| 产物 | `_build/out/AutoMeasureSort.ino.hex`（50,156 B）、`.elf`、`.eep`、`with_bootloader.*` |

**`--warnings all`（= `-Wextra`）的差异**：会多出 5 条警告，**全部来自 Arduino core 的 `new.cpp`**（`unused parameter 'tag'`），不是本工程代码。验收口径统一用 `--warnings more`。

> 顺带：`90_历史存档/GeometricSortingTest/GeometricSortingTest.ino` 同样 0 错 0 警告。

## 5 结论

- ✅ AI 报告里"avr-g++ 7.3.0 语法编译通过（0 错 0 警告）"**可复现**，但需要明确的 include 路径与命令（见 §3）
- ✅ 计划 1-6 的验收点从"口头"变成"可执行"：`10_主控_Arduino/compile.ps1`
- ❗ 报告里"SRAM 3463B / Flash 12952B"是**整合版 GeometricSorting** 的数，不是 AMS 的；AMS 实测是 **Flash 17,824 B / RAM 1,369 B**，别混用
