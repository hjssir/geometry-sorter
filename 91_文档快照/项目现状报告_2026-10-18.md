## 1. 项目目标推测

本项目是一台**教学/竞赛用的几何体自动分拣演示装置**：以 Arduino Mega 2560 为实时主控，三级直流传送带把几何体送到识别工位，K230 视觉模块拍照识别并回传类别与置信度，主控据此停带、驱动 6 位分选转盘（闭环步进）与 80° 开合机构完成落料，TJC 串口屏同步显示识别结果；全过程上电自动循环、无需上位机。

当前阶段按已确认的 A2 决策 **以"随机 6 选 1"作为演示逻辑**，尚未要求"类别 → 固定盒位"的真实分拣规则。系统定位是"先跑通闭环、再谈分拣正确率"。

**依据**：`智能体运行日志/2026-10-16_本次会话工作总结.md`、`目前到现在的所有资料/AutoMeasureSort/README.md`、`目前到现在的所有资料/AutoMeasureSort/AutoMeasureSort.ino`、`智能体运行日志/10.14_GeometricSorting_工作日志.md`。

### 3.3 通信约定 1：K230 → Arduino

| 项目 | 当前实现（det_video.py） | 已确定的目标态（A5=1） | 状态 |
|---|---|---|---|
| 波特率 | 115200 | 115200 | ✅ 一致 |
| 触发词 | `image`（5 字节，**无结束符**） | 不变 | ⚠️ 见下方风险表 |
| 正常回包 | `类别名 + " " + 两位小数 + "\n"`，例 `红球体 0.95\n` | **`<数字id> <置信度>\n`**，例 `37 0.95\n` | ❌ 待视觉改 |
| 未识别 | **什么都不发** | 建议增加 `NONE\n`（见下） | ❌ 待视觉改 |
| 置信度门槛 | 后处理用 config 的 `confidence_threshold`，回包硬编码 `>0.6` | 统一为一个值 | ⚠️ 双轨 |
| Arduino 解析 | `tagToId()`：纯数字才得 id，否则 -1 | 保持不动 | ✅ 不用改 |
| 帧缓冲 | `VISION_FRAME_MAX=48`、`TAG_MAX_LEN=16`、静默期 20ms | 不变（改数字后更宽裕） | ✅ |

**依据**：`det_video.py:182–187、222–224、238–240`；`AutoMeasureSort.ino:74–76、175–205`；`GeometricSortingTest.ino:88–90、252–315`。

**`[调试提示]` 这条链路不通时，排查顺序是固定的三步**：
1. **有没有字节**：让 K230 单独发一次，Arduino USB 日志里完全没有反应 → 先怀疑**物理层**（TX/RX 是否交叉、共地、K230 脚本是否在跑、波特率）。
2. **有字节但日志打印"标签=-1"** → 不是物理问题，是**标签形态问题**（K230 发了中文名），找视觉同学。
3. **日志里连"收到无效帧"都没有** → 是**帧边界问题**（缺 `\n`、半帧、被 flush 掉），看下方风险表。

**`[背景补充]` 为什么"未识别也要回 `NONE`"是必须的**：已确定"漏检重试后放行 + 掉线停机"两种不同处理。K230 只在看到物体时才说话，那么"没说话"既可能是**空载**（正常）、也可能是**漏检**、还可能是**脚本崩了/线松了**——三种情况无法区分。加一个 `NONE` 应答后，Arduino 就能判：有 `NONE` = K230 活着只是没看到（继续送带）；连续无任何回复 = 真掉线（停机等人）。**这条不解决，异常策略落不了地。**

**当前实现的 4 个已知风险（都是"静默失败"）**

| 风险 | 机制 | 你会看到的现象 | 定位 |
|---|---|---|---|
| R1 触发粘连 | `uart.read(10)` 读到 `imageimage` ≠ `'image'` → 整段丢弃，无 ACK | 偶发"发了没反应"，靠超时重发 | `det_video.py:182–187` |
| R2 触发分片 | 读到 `imag`+`e` 两段都不等 → 触发丢失 | 同上 | `det_video.py:186–187` |
| R3 调色板越界 | `color_four` 只有 **80** 项，类别序号 ≥80 → 异常退出 → 永久不回应 | **前几件正常，某件之后 K230 彻底没反应，重启 K230 又好** | `det_video.py:43–63、229–232、245–260` |
| R4 双阈值 | 后处理按 config 阈值、回包硬编码 0.6 | 屏上画了框、日志里识别到，但 Arduino 一直等消息 | `det_video.py:104、212、223` |

| 项目 | 约定 | 依据 |
|---|---|---|

| 文本 | `t0.txt="DETECT"` | `AutoMeasureSort.ino:214–218、277` |

| 图片（未使用） | `p<n>.pic=<图片号>` | `hmi.cpp:105–118`（**0 次调用**） |
| 数据列表（未使用） | `data0.insert("序号^名称^数量")` | `hmi.cpp:125–136`（**0 次调用**） |

**❌ 关键冲突（三方核对的核心结论）**：`ji.HMI` 里 `t0/t1/t2` 的类型码是 `'t'`（文本控件），属性表为 `sta / style / key / borderc / borderw / font / bco / picc / pic / pco / xcen / ycen / pw / txt / txt_maxl / isbr / spax / spay / codesdown-0 / codesup-0`，**没有 `val`**。淘晶驰官方规则：`txt` 是字符串属性、`val` 是数字控件（`n` 类型）的属性（见[官方文档](http://wiki.tjc1688.com/QA/QA11.html)、[文本控件属性表](http://wiki.tjc1688.com/widgets/Text.html)）。→ 现在发 `t1.val=12` 屏上**永远不变**。

已确认 A5=1，因此改为：**HMI 同学把 `t1/t2` 的控件类型改成"数字控件"，objname 保持 `t1`/`t2` 不变** → Arduino 代码一行都不用改。

**`[调试提示]` 判断"屏到底收没收到指令"的方法**：把 Serial1 的 RX 也接出来（或临时在 Arduino 里把 `Serial1` 收到的字节打印到 USB 日志）。屏收到格式错误的指令会回 `1C FF FF FF` 之类的错误码；如果 Arduino 发完能收到这个回包 → 线是通的、是**指令格式/属性名**的问题；如果什么都收不到 → 是**波特率/接线**问题。这能在 10 分钟内区分"HMI 问题"还是"我的串口问题"。

**`[调试提示]` 中文显示**：官方明确 Arduino 默认 UTF-8、串口屏默认 GB2312，编码不一致会**乱码或不显示**（见[官方说明](http://wiki.tjc1688.com/widgets/Text.html)）。本轮建议：**屏上只显示数字（1..13 / 1..31），不要发中文状态词**。整合版 `hmiUpdateStatus("启动输送")` 就在发中文，属于潜在乱码源——主线程序（AutoMeasureSort）目前没调它，保持这个状态即可。
